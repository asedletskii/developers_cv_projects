# Видение продукта

## Проблема

Разработчик, который ищет работу, отправляет одно и то же PDF-резюме десяткам адресатов и ничего не знает о том, что с ним происходит дальше:

- открыли ли резюме, и кто именно — рекрутер, техлид, коллега, которому переслали;
- что в нём прочитали, а что пролистали;
- почему не ответили.

Кроме того, PDF плохо показывает то, что важно в IT: стек по местам работы и проектам, ссылки на код, живые проекты. А контакты в открытом виде собирают парсеры и спам-рассылки.

## Решение

**developers-cv.ru** — сервис интерактивных резюме для разработчиков:

1. **Кабинет** — кандидат собирает резюме из структурированных секций (опыт, стек, проекты, образование…), настраивает оформление и публикует.
2. **Публичная страница** — адаптивная интерактивная страница резюме: навигация по секциям, фильтр «где я использовал эту технологию», тёмная и светлая темы, печать, скачивание файла.
3. **Именованные ссылки** — отдельная ссылка на каждого адресата («Яндекс, рекрутер Анна»). Ссылку можно выключить, не трогая остальные, и по ней видно просмотры.
4. **Аналитика и уведомления** — кто, когда и как читал резюме по каждой ссылке (в разработке).
5. **Защита контактов** — скрытые контакты не попадают в HTML и JSON страницы, а выдаются отдельным запросом по клику.

## Цели

| # | Цель | Метрика успеха | Целевое значение | Статус |
|---|---|---|---|---|
| G1 | Кандидат быстро собирает резюме | Медианное время от создания резюме до первой публикации | ≤ 30 мин | измерение не настроено |
| G2 | Резюме доходит до адресата | Доля созданных ссылок, у которых есть ≥ 1 прочтение (см. [термины аналитики](../../docs/analytics/README.md#термины)) | ≥ 60 % | после EP-ANL |
| G3 | Кандидат понимает реакцию | Доля активных кандидатов, заходивших во вкладку «Аналитика» за неделю | ≥ 50 % | после EP-ANL |
| G4 | Контакты защищены от парсинга | Доля публичных ответов, содержащих значение скрытого контакта | 0 % | достигнуто ([FR-CNT-003](../03-functional/FR-CNT.md)) |
| G5 | Страница открывается быстро с телефона | LCP публичной страницы, p75, мобильный 4G | ≤ 2,5 с | измерение не настроено ([NFR-PERF-01](../04-non-functional/performance-reliability.md)) |

**North Star Metric:** число прочтений резюме по именованным ссылкам в неделю. Метрика объединяет и активность кандидатов (создают ссылки и рассылают), и ценность для них (резюме реально читают).

## Границы

### В скоупе

- Кабинет кандидата: профиль, несколько резюме, редактор секций, оформление, статус публикации.
- Публичная страница резюме по именованной ссылке.
- Управление ссылками: создание, выключение, удаление, счётчики.
- Скрытые контакты с раскрытием по клику.
- Аналитика просмотров и уведомления (в разработке).
- Интерфейс на русском и английском; резюме — на одном из 7 языков.

### Вне скоупа

| Что | Почему |
|---|---|
| Поиск резюме, каталог кандидатов, сторона работодателя | Продукт — инструмент кандидата, а не job board |
| Генерация PDF на сервере | Кандидат даёт ссылку на свой файл (`resumeLink`); печать страницы покрывает остальное |
| Загрузка файлов (фото, скриншоты) | Сейчас все медиа — внешние `http(s)`-ссылки. MinIO поднят в проде, но не используется ([GAP-08](../06-gaps-and-risks.md#технический-долг)) |
| Импорт из hh.ru / LinkedIn | Идея, не приоритет |
| Идентификация личности посетителей (fingerprinting, деанонимизация) | Юридический и репутационный риск, см. [nice-to-have аналитики](../../docs/analytics/nice-to-have.md#4-сознательно-не-делаем) |
| Сторонние счётчики (Метрика, GA) на публичной странице | Передача данных посетителей третьим лицам |

## Допущения

- A1. Один кандидат — один пользователь; совместного редактирования резюме нет.
- A2. На одну ссылку приходятся десятки, редко сотни визитов. Хранилище и отчёты рассчитаны на такие объёмы ([NFR-PERF-05](../04-non-functional/performance-reliability.md)).
- A3. Посетитель публичной страницы не регистрируется и не авторизуется.
- A4. Сервис работает в одном регионе (РФ), один инстанс бэкенда за Caddy.

## Ограничения

- C1. **Аутентификация — заглушка.** Пользователь определяется заголовком `X-Mock-User-ID`, пользователи заводятся миграциями. Реальная регистрация и вход — обязательное условие публичного запуска ([US-ACC-01](../02-user-stories/EP-ACC.md), [RISK-01](../06-gaps-and-risks.md#реестр-рисков)).
- C2. Хранение персональных данных — по 152-ФЗ; сервер в РФ.
- C3. Стек: Go (Gin, GORM, PostgreSQL 17), React 19 + TypeScript + Vite + MUI 7 + Redux Toolkit, Caddy, Docker Compose. Изменение стека — отдельное решение.
