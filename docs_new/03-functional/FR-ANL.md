# FR-ANL. Аналитика просмотров

Истории: [EP-ANL](../02-user-stories/EP-ANL.md). Технический проект с контрактами и схемой БД — [docs/analytics/backend.md](../../docs/analytics/backend.md) и [frontend.md](../../docs/analytics/frontend.md). Здесь — что система должна делать; как — в проекте.

## Сбор

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ANL-001 | Сервер должен фиксировать событие `view` на каждую успешную выдачу публичной проекции и `contact_view` на каждое успешное раскрытие контакта, с идентификатором ссылки и временем | Must | Реализовано | `resume_link_events`. Тип раскрытого контакта не сохраняется |
| FR-ANL-002 | Каждая загрузка страницы должна получать серверный идентификатор визита (`X-View-Id`), а браузер — идентификатор посетителя в first-party cookie `__Secure-cv_vid` (случайный UUID, `Path=/api/v1/cv`, `HttpOnly`, `Secure`, `SameSite=Lax`, 1 год). Без cookie — суточный идентификатор из хешей IP и User-Agent | Must | План | [Идентификация посетителя](../../docs/analytics/backend.md#идентификация-посетителя) |
| FR-ANL-003 | Визиты владельца резюме (запрос с действующей сессией `__Host-session` владельца резюме ссылки) помечаются `owner` и не входят в отчёты. Проверка сессии на публичной ручке не пишет WARN и метрики отказов, если cookie нет или сессия недействительна. Предпросмотр в кабинете не создаёт визитов | Must | План | Аутентификация через Telegram уже есть; нужен необязательный путь проверки сессии — [классификация трафика](../../docs/analytics/backend.md#классификация-трафика) |
| FR-ANL-004 | Визиты классифицируются: `bot` — по списку User-Agent роботов и headless-браузеров; `suspect` — всплеск (один IP открыл больше 5 разных ссылок за 60 с); иначе `human`. Помеченные визиты хранятся, но не входят в отчёты | Must | План | [Классификация трафика](../../docs/analytics/backend.md#классификация-трафика) |
| FR-ANL-005 | Визит становится «прочтением», когда клиент сообщает не меньше 5 секунд активного (видимого) времени | Must | План | |
| FR-ANL-006 | Клиент отправляет поведенческие события пачкой в `POST /api/v1/cv/:linkId/events` через `sendBeacon` (раз в 15 с и при скрытии страницы). Ручка идемпотентна по идентификатору события, принимает `text/plain` и `application/json`, отвечает `204` | Should | План | |
| FR-ANL-007 | Предпросмотр в кабинете и страница без `X-View-Id` не отправляют событий | Must | План | |

## Отчёты

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ANL-010 | `GET /lk/link/:linkId/statistics` возвращает за период: открытия, прочтения, уникальных и вернувшихся посетителей, раскрытия контактов, скачивания, дату первого и последнего просмотра (за всё время), медианное активное время, разбивку по устройствам и источникам, число отфильтрованных визитов по причинам | Must | Частично | Сейчас — только `{ views, contactViews }` без фильтрации |
| FR-ANL-011 | Период задаётся `from`, `to` (по умолчанию 30 дней) и часовым поясом `tz` (IANA, по умолчанию `UTC`) | Must | План | |
| FR-ANL-012 | `GET /lk/link/:linkId/views` — лента визитов с пагинацией курсором (по 20): время, порядковый номер посетителя и признак «вернувшийся», устройство, браузер, ОС, источник, признак прочтения, активное время, самая дальняя секция, секция ухода, события визита. Идентификатор посетителя наружу не отдаётся | Must | План | |
| FR-ANL-013 | `GET /lk/link/:linkId/statistics/daily` — открытия, прочтения, уникальные посетители по дням в поясе `tz`; дни без визитов — нули | Should | План | |
| FR-ANL-014 | `GET /lk/resume/:resumeId/statistics` — сводка по всем ссылкам резюме плюс таблица ссылок (открытия, прочтения, последний просмотр) | Should | План | Счётчики в строках ссылок берутся отсюда одним запросом |
| FR-ANL-015 | Вкладка «Аналитика» кабинета: выбор ссылки («Все ссылки» или конкретная), период 7/30/90 дней, плашки с числами, лента визитов, график по дням (скрыт при < 3 открытий), пустые состояния | Must | План | Сейчас — заглушка «Аналитика скоро появится» |

## Поведение на странице

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ANL-020 | Секция считается просмотренной, если ≥ 40 % её высоты (или ≥ 50 % экрана для высоких секций) видно не меньше 1 с. Событие `section_view` — один раз за визит на секцию | Should | План | |
| FR-ANL-021 | Клиент сообщает самую дальнюю просмотренную секцию и секцию, видимую в момент ухода; отчёт `statistics/sections` показывает для каждой секции «дошли» и «ушли здесь» по прочтениям | Should | План | |
| FR-ANL-022 | Выбор и сброс технологии в фильтре — событие `tech_filter`; отчёт `statistics/technologies` — число выборов и посетителей по технологии | Could | План | |
| FR-ANL-023 | Клик по «Скачать резюме» — событие `download`; клик по внешней ссылке — `external_click` с типом и хостом | Should | План | |

## Карта кликов

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ANL-030 | Клики внутри секций собираются с координатами относительно секции (сотые доли процента ширины и высоты секции), шириной экрана и целевым элементом; отчёт отдаёт сетку 20×20 по секции и брейкпоинту | Could | План | Не больше 200 кликов на визит |
