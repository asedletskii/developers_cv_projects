# FR-NTF. Уведомления

Истории: [EP-NTF](../02-user-stories/EP-NTF.md). Технический проект — [docs/analytics/backend.md → Уведомления](../../docs/analytics/backend.md#уведомления).

## Архитектура доставки

```
команда записи визита / батча / раскрытия
   └─ в той же транзакции: INSERT analytics_outbox (dedup_key UNIQUE)
воркер в процессе бэкенда (каждые 5 с)
   └─ SELECT … FOR UPDATE SKIP LOCKED → адаптер канала (Telegram) → sent_at
```

## Требования

### Канал Telegram

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-NTF-001 | `POST /lk/notifications/telegram/link` выдаёт одноразовую ссылку `https://t.me/<бот>?start=<токен>`, токен живёт 15 минут | Must | План | |
| FR-NTF-002 | Вебхук бота `POST /api/v1/integrations/telegram/webhook` принимает запросы только с корректным `X-Telegram-Bot-Api-Secret-Token`, по токену из `/start` привязывает `chat_id` к пользователю и отвечает в чат подтверждением | Must | План | |
| FR-NTF-003 | Просроченный или использованный токен — бот отвечает, что ссылка устарела | Must | План | |
| FR-NTF-004 | `DELETE /lk/notifications/telegram` отвязывает бота; бот сообщает об отключении. Если пользователь заблокировал бота, при ошибке доставки `403` привязка снимается автоматически | Must | План | |
| FR-NTF-005 | `GET/PUT /lk/notifications/settings` — флаги `onOpen` (по умолчанию выкл.), `onRead` (вкл.), `onContact` (вкл.) | Should | План | |

### События

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-NTF-010 | Визит, ставший прочтением ([FR-ANL-005](FR-ANL.md)), порождает уведомление `link_read` с названием ссылки, устройством, источником, активным временем, самой дальней секцией, признаком «заходил раньше» и ссылкой на ленту визитов | Must | План | |
| FR-NTF-011 | Визиты с пометкой `owner`, `bot`, `suspect` уведомлений не порождают | Must | План | |
| FR-NTF-012 | Раскрытие скрытого контакта порождает уведомление `contact_revealed` с типом контакта | Should | План | Требует сохранять тип контакта в событии |
| FR-NTF-013 | Открытие (без прочтения) порождает `link_opened`, если включено `onOpen` | Could | План | |

### Надёжность и анти-спам

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-NTF-020 | Дедупликация по ключу: `link_read` — не чаще раза в сутки на пару (ссылка, посетитель); `contact_revealed` — раз на (визит, контакт) | Must | План | `dedup_key UNIQUE` |
| FR-NTF-021 | Доставка — не меньше одного раза: до 5 попыток с экспоненциальной паузой; после исчерпания — запись в лог и метрику `notifications_failed_total` | Must | План | |
| FR-NTF-022 | Уведомление должно уходить не позже 30 секунд после события (p95) | Should | План | NFR-PERF-06 |
| FR-NTF-023 | Тихие часы: если пользователь задал интервал, уведомления внутри него копятся и уходят одной сводкой по окончании | Could | Идея | |
