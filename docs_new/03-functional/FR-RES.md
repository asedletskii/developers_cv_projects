# FR-RES. Резюме: создание, версии, статусы, удаление

Истории: [EP-RES](../02-user-stories/EP-RES.md).

## Требования

### Список, создание, чтение

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-RES-001 | `GET /lk/resumes` должен возвращать `200` и массив резюме пользователя `{ id, title, language, status, version }`. Пустой список — `[]`. Порядок не гарантируется | Must | Реализовано | Кандидат на улучшение: сортировка по `updatedAt desc` |
| FR-RES-002 | `POST /lk/resume` с телом `{ title, language }` должен создавать резюме в статусе `draft` с версией `1` и отвечать `201 {"id"}` | Must | Реализовано | |
| FR-RES-003 | `title` обязателен и непуст после обрезки; `language` — из справочника языков резюме. Иначе `400` | Must | Реализовано | Максимальной длины названия нет — см. FR-RES-008 |
| FR-RES-004 | Все операции с резюме доступны только владельцу. Чужое или несуществующее резюме — `404` | Must | Реализовано | Покрыто `ownership_write_integration_test.go` |
| FR-RES-005 | Пользователь может иметь несколько резюме на одном языке | Should | Реализовано | Ограничение `UNIQUE (user_id, language)` снято миграцией `000006`. [`docs/api`](../../docs/api/resumes.md) описывает старое поведение ([GAP-01](../06-gaps-and-risks.md#расхождения)) |
| FR-RES-006 | `GET /lk/resume/:resumeId` должен возвращать резюме целиком: `id, title, language, status, version, createdAt, updatedAt, overview`, секции-одиночки `profile, contacts, skills` (только если созданы) и массивы `languages, technologies, experiences, educations, courses, activities, projects` (пустые — `[]`) | Must | Реализовано | У элементов списков есть `id`, по которому клиент сохраняет идентичность записи |
| FR-RES-007 | `PUT /lk/resume/:resumeId` с телом `{ version, title }` должен менять название и отвечать `204`. Язык после создания не меняется | Should | Реализовано | |
| FR-RES-008 | Название резюме должно быть не длиннее 128 символов | Should | План | Сейчас длина не ограничена |
| FR-RES-009 | При создании резюме должен создаваться обзор со значениями по умолчанию: приветствие — четыре пустые строки, секции — `[]`, без темы, доступности и ссылки на файл. Остальные секции не создаются | Must | Реализовано | |

### Версии

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-RES-010 | У резюме одна версия на весь агрегат. Любое изменение — название, статус, любая секция — увеличивает её на 1 и обновляет `updatedAt` | Must | Реализовано | `resume/infrastructure/persistence/repository/resume.go` |
| FR-RES-011 | Любой изменяющий запрос к резюме и его секциям должен содержать актуальную `version`. Устаревшая — `412`, изменение не применяется; `version < 1` — `400` | Must | Реализовано | Формат ответа `412` — [FR-API-010](README.md#ошибки) |

### Статусы

```
            publish                close
  draft ───────────────▶ opened ───────────▶ closed
                           ▲                   │
                           └───────────────────┘
                                 publish
```

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-RES-020 | Резюме имеет статус `draft` (черновик), `opened` (опубликовано) или `closed` (скрыто). Новое резюме — `draft` | Must | Реализовано | `CHECK resumes_status_check` |
| FR-RES-021 | `PUT /lk/resume/:resumeId/status` с телом `{ status, version }` должен выполнять переход и отвечать `204`. Допустимые переходы: `draft → opened`, `closed → opened`, `opened → closed` | Must | Реализовано | `domain.Resume.Publish/Close` |
| FR-RES-022 | Недопустимый переход (включая `opened → opened`, любой переход в `draft`) — `409 CONFLICT "Invalid resume status transition"`. Неизвестный статус — `400` | Must | Реализовано | |
| FR-RES-023 | Публичная проекция и раскрытие контактов должны быть доступны только для резюме в статусе `opened`. Для остальных статусов — `404`, как для несуществующего | Must | Реализовано | `readers/resume.go` |

### Удаление

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-RES-030 | `DELETE /lk/resume/:resumeId` должен удалять резюме в любом статусе вместе с секциями, ссылками и событиями аналитики и отвечать `204`. Операция необратима | Must | Реализовано | Каскад внешних ключей. Версия не проверяется |
| FR-RES-031 | Интерфейс должен запрашивать подтверждение удаления с названием резюме | Must | Реализовано | «Удалить резюме «…» безвозвратно?» |

## Модель данных

```
resumes (id, user_id → users, title, language, status, version, created_at, updated_at)
 ├─ resume_overviews           1:1, создаётся вместе с резюме
 ├─ resume_profiles            1:0..1
 ├─ resume_contacts            1:0..1 ─ resume_contact_hidden, resume_contacts_text
 ├─ resume_skills              1:0..1 ─ hard/soft списки
 ├─ resume_languages           1:N, position
 ├─ resume_technologies        1:N, position
 ├─ resume_experiences         1:N ─ achievements, resume_experience_stack
 ├─ resume_educations          1:N
 ├─ resume_courses             1:N
 ├─ resume_activities          1:N
 ├─ resume_projects            1:N ─ screenshots, stack, contributors
 └─ resume_links               1:N ─ resume_link_events
```

Все дочерние таблицы связаны с `resumes` через `ON DELETE CASCADE`.
