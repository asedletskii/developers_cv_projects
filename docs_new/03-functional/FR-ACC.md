# FR-ACC. Доступ к кабинету и профиль пользователя

Истории: [EP-ACC](../02-user-stories/EP-ACC.md).

## Требования

### Аутентификация и авторизация

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ACC-001 | Все ручки `/api/v1/lk/*` должны требовать аутентифицированного пользователя. Без него — `401 UNAUTHORIZED "Authentication required"` | Must | Реализовано | Сейчас — заглушка: заголовок `X-Mock-User-ID: <uuid>` существующего в `users` пользователя (`user/infrastructure/auth/mock.go`) |
| FR-ACC-002 | Система должна поддерживать регистрацию и вход через внешний провайдер (кандидаты: Яндекс ID, GitHub, Telegram Login) с сессией в `HttpOnly; Secure; SameSite=Lax` cookie | Must | План | Выбор провайдеров — ADR. Блокер публичного запуска ([RISK-01](../06-gaps-and-risks.md#реестр-рисков)) |
| FR-ACC-003 | Идентичность пользователя должна определяться только сессией. Идентификатор пользователя в URL кабинета, заголовке или теле не должен влиять на то, чьи данные возвращаются | Must | Частично | Бэкенд берёт пользователя из middleware. Фронт подставляет `X-Mock-User-ID` из адреса `/cv/lk/:userId` — любой, кто знает UUID, открывает чужой кабинет ([GAP-03](../06-gaps-and-risks.md#расхождения)) |
| FR-ACC-004 | Выход должен инвалидировать сессию на сервере; последующие запросы с ней — `401` | Must | План | |
| FR-ACC-005 | Сессия должна истекать через 30 дней неактивности; активность продлевает её (sliding expiration) | Should | План | |

### Профиль пользователя

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ACC-010 | `GET /lk/profile` должен возвращать `200 { userId, ru, en, photoPath? }`, где `ru` и `en` — объекты `{ name?, surname?, patronymic?, position?, location? }`. Незаполненные поля отсутствуют в ответе | Must | Реализовано | `user/application/queries/get_profile.go` |
| FR-ACC-011 | Если у пользователя нет профиля — `404 NOT_FOUND "Profile not found"`. Фронт показывает экран «Личный кабинет не найден»; при 5xx — «Не удалось загрузить личный кабинет» | Must | Реализовано | |
| FR-ACC-012 | `PUT /lk/profile` с телом `{ ru, en, photoPath? }` должен полностью заменять профиль и отвечать `204` | Must | Реализовано | |
| FR-ACC-013 | `name` и `surname` каждого языка необязательны, но если переданы, должны быть непустыми после обрезки. Иначе `400 "Invalid profile"` | Must | Реализовано | `user/domain/profile.go` |
| FR-ACC-014 | `photoPath`, если передан, должен быть абсолютной `http(s)`-ссылкой с хостом. Иначе `400 "Invalid profile"` | Must | Реализовано | |
| FR-ACC-015 | Фронт должен показывать профиль на языке интерфейса, подставляя вместо незаполненного английского поля русское | Should | Реализовано | `getLocalizedProfile` |

### Жизненный цикл аккаунта

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-ACC-020 | Система должна позволять пользователю удалить аккаунт. Удаление каскадно удаляет профиль, резюме со всеми секциями, ссылки, события аналитики, настройки уведомлений. Операция необратима и требует явного подтверждения | Must | План | Внешние ключи с `ON DELETE CASCADE` уже заложены в схеме |

## Модель данных

```
users (id, created_at, updated_at)
 ├─ user_profiles (user_id PK, photo_path)
 └─ user_profile_localizations (user_id, language ∈ {ru,en}, name, surname, patronymic, position, location)
```

Демо-пользователи создаются миграцией `000001_users`: `10000000-0000-0000-0000-000000000001` и `…0002`.

## Отличие профиля пользователя от профиля резюме

| | Профиль пользователя | Профиль резюме (секция «Обо мне») |
|---|---|---|
| Сколько | один на пользователя | один на резюме |
| Языки | `ru` и `en` одновременно | язык резюме |
| Обязательные поля | нет (имя и фамилия непустые, если заданы) | имя, фамилия, вакансия, фото, дата рождения, город |
| Где виден | карточка в кабинете | публичная страница |
| Связь | источник для кнопки «Как в профиле» ([FR-EDT-114](FR-EDT.md)) | копия на момент заполнения, дальше независима |
