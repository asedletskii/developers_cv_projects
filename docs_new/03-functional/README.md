## FR-API. Общие правила HTTP API

Применяются ко всем ручкам, если в требовании домена не сказано иное.

### Адресация и формат

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-API-001 | Все ручки приложения должны находиться под префиксом `/api/v1`. Кабинетные — под `/api/v1/lk`, публичные — под `/api/v1/cv`. Служебные (`/health`, `/ready`, `/metrics`) — в корне | Must | Реализовано | `platform/http/router.go` |
| FR-API-002 | В проде фронтенд и API должны обслуживаться с одного origin: Caddy проксирует `/api/*` на бэкенд, остальное отдаёт как SPA с fallback на `index.html` | Must | Реализовано | `frontend/Caddyfile` |
| FR-API-003 | Тела запросов и ответов — JSON в UTF-8 | Must | Реализовано | |
| FR-API-004 | Сервер должен отклонять тело с неизвестным полем или с несколькими JSON-значениями подряд ответом `400 BAD_REQUEST "Invalid request body"` | Must | Частично | `platform/http/json/binder.go`. `PUT /lk/profile` использует нестрогий `ShouldBindJSON` ([GAP-09](../06-gaps-and-risks.md#расхождения)) |
| FR-API-005 | Строковые поля должны обрезаться по краям. Пустая после обрезки строка для обязательного поля — ошибка `400`, для необязательного — то же, что отсутствие поля | Must | Реализовано | |
| FR-API-006 | Идентификаторы сущностей — UUID. Сервер генерирует их для новых сущностей. Невалидный UUID в пути или теле — `400` (`Invalid resume id`, `Invalid link id`) | Must | Реализовано | |
| FR-API-007 | `PUT` — полная замена ресурса: поля, которых нет в теле, сбрасываются (необязательные) или дают `400` (обязательные). Частичного обновления (`PATCH`) нет | Must | Реализовано | |
| FR-API-008 | Успешные ответы: `POST` создания → `201 {"id": "<uuid>"}`; `PUT` и `DELETE` → `204` без тела; чтение → `200` | Must | Реализовано | |

### Ошибки

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-API-009 | Тело любой ошибки: `{"error": {"code": "<КОД>", "message": "<текст>", "requestId": "<uuid>"}}`. `requestId` дублируется в заголовке `X-Request-ID` | Must | Частично | Исключения — FR-API-010 |
| FR-API-010 | Ответ `412 Precondition Failed` на конфликт версий должен иметь то же тело ошибки с кодом `PRECONDITION_FAILED` | Should | Частично | Ссылки — с телом. Резюме и секции — `412` без тела; `PUT /status` при `version < 1` — `{"error": "version must be positive"}` строкой ([GAP-04](../06-gaps-and-risks.md#расхождения)) |
| FR-API-011 | Коды ошибок: `400 BAD_REQUEST`, `401 UNAUTHORIZED`, `404 NOT_FOUND`, `409 CONFLICT`, `412 PRECONDITION_FAILED`, `413 REQUEST_TOO_LARGE`, `429 TOO_MANY_REQUESTS`, `500 INTERNAL_ERROR`. Текст `500` не раскрывает внутренних деталей | Must | Реализовано | `platform/http/errors` |
| FR-API-012 | Запрос к чужому или несуществующему ресурсу должен отвечать `404`, а не `403`, чтобы не раскрывать существование ресурса | Must | Реализовано | |
| FR-API-013 | Неизвестный маршрут — `404 NOT_FOUND "Route not found"` в стандартном формате | Should | Реализовано | |

### Конкурентный доступ

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-API-014 | Изменяемые ресурсы с версией (резюме, ссылка) должны принимать поле `version` в теле изменяющего запроса. Если оно не совпадает с текущей версией — `412`, изменение не применяется. `version < 1` — `400` | Must | Реализовано | Оптимистичная блокировка `UPDATE … WHERE version = ?` |
| FR-API-015 | Успешное изменение увеличивает версию ровно на 1. Ответ `204` новую версию не возвращает; клиент либо перечитывает ресурс, либо сам прибавляет 1 | Must | Реализовано | Кандидат на улучшение: заголовок `ETag` с новой версией |

### Форматы значений

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-API-016 | Форматы дат: дата `YYYY-MM-DD`, год-месяц `YYYY-MM`, год `YYYY`, момент времени — RFC 3339 в UTC | Must | Реализовано | |
| FR-API-017 | Внешние ссылки должны быть абсолютными `http`/`https` с хостом, без пробелов. Относительные пути и другие схемы (`javascript:`, `data:`) — `400` | Must | Реализовано | Проверка в домене и `CHECK` в БД |
| FR-API-018 | Цвета — `#RGB` или `#RRGGBB` | Must | Реализовано | |
| FR-API-019 | Значения справочников (enum) передаются строками в точном написании из [справочника](#справочники). Любое другое — `400` | Must | Реализовано | |

### Защита

| ID | Требование | Приоритет | Статус | Комментарий |
|---|---|---|---|---|
| FR-API-020 | Сервер должен ограничивать частоту запросов с одного IP (по умолчанию 50 в секунду, всплеск 100; настраивается `RATE_LIMIT_*`). Превышение — `429` | Must | Реализовано | См. [GAP-07](../06-gaps-and-risks.md#расхождения) про доверенные прокси |
| FR-API-021 | Сервер должен отклонять тело больше `HTTP_MAX_BODY_BYTES` (по умолчанию 1 МиБ) ответом `413` | Must | Реализовано | |
| FR-API-022 | Запросы с `Origin`, которого нет в `CORS_ALLOWED_ORIGINS`, должны получать `403`. Запросы без `Origin` (same-origin `GET`, серверные клиенты) проходят | Should | Реализовано | В проде CORS не участвует, так как всё same-origin |
