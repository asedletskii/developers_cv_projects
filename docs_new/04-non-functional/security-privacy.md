# Безопасность и персональные данные

## Безопасность (NFR-SEC)

| ID | Требование | Метрика и цель | Проверка | Сейчас | Статус |
|---|---|---|---|---|---|
| NFR-SEC-01 | Настоящая аутентификация | Вход через внешнего провайдера (OAuth 2.0 / OIDC); сессия в cookie `HttpOnly; Secure; SameSite=Lax`, идентификатор сессии ≥ 128 бит случайности; защита от CSRF для изменяющих запросов (`SameSite` + проверка `Origin`) | Security review, e2e-тест входа и выхода | Заглушка `X-Mock-User-ID` | План |
| NFR-SEC-02 | Заглушка аутентификации невозможна в проде | Старт с `APP_ENV=production` при включённом mock-аутентификаторе завершается ошибкой конфигурации | Тест `validateProductionSecurity` | Mock-аутентификатор подключён безусловно (`app/wire.go`), в том числе в проде | План |
| NFR-SEC-03 | Изоляция данных пользователей | Каждый запрос к данным кабинета фильтрует по `user_id` из сессии на уровне SQL; чужой ресурс — `404`. **100 %** изменяющих ручек покрыты тестом «чужой пользователь получает 404» | Интеграционные тесты владения | Бэкенд: так (`ownership_write_integration_test.go`). Фронт: `userId` берётся из URL ([GAP-03](../06-gaps-and-risks.md#расхождения)) | Частично |
| NFR-SEC-04 | Только HTTPS | Все ответы по HTTPS; `Strict-Transport-Security: max-age=31536000; includeSubDomains` на всех ответах (статика и API); HTTP → 301 на HTTPS | `curl -I`, SSL Labs ≥ A | Caddy выпускает сертификат и редиректит при заданном домене. HSTS ставит только бэкенд и только при `HTTP_TLS_ENABLED=true`, а в проде TLS терминирует Caddy — заголовка нет ни на статике, ни на API | Частично |
| NFR-SEC-05 | Заголовки безопасности | API: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cache-Control: no-store`. Статика: CSP с `script-src 'self'`, `frame-ancestors 'none'` | securityheaders.com ≥ A; тест `security_test.go` | API — так. Caddy заголовков для статики не ставит | Частично |
| NFR-SEC-06 | Защита от злоупотреблений | Рейт-лимит по реальному IP клиента (50 rps, всплеск 100); отдельный лимит на раскрытие контактов (FR-CNT-015); лимит тела 1 МиБ; `HTTP_TRUSTED_PROXIES` указывает на Caddy | Тест middleware; проверка конфига прода | Лимиты есть; доверенные прокси в `.env.example` пусты — за Caddy все клиенты видны с одного IP ([GAP-07](../06-gaps-and-risks.md#расхождения)) | Частично |
| NFR-SEC-07 | Валидация на сервере, а не только в интерфейсе | Строгий JSON (неизвестные поля — `400`), whitelist для enum, только `http(s)`-ссылки (исключает `javascript:` в ссылках резюме). Фронт не использует `dangerouslySetInnerHTML` для пользовательских данных | Тесты валидаторов; ESLint-правило `react/no-danger` | Так, кроме нестрогого разбора `PUT /lk/profile` ([GAP-09](../06-gaps-and-risks.md#расхождения)); `dangerouslySetInnerHTML` не используется | Реализовано |
| NFR-SEC-08 | Уязвимые зависимости не попадают в прод | Сборка падает при известной уязвимости в достижимом коде Go; для фронта — еженедельный отчёт и PR с обновлениями | govulncheck в CI; Dependabot или Renovate | govulncheck — есть; для фронта — нет | Частично |
| NFR-SEC-09 | Служебные эндпоинты не доступны из интернета | `/metrics`, `/ready`, `/health` не проксируются наружу; порты бэкенда, PostgreSQL, MinIO, NATS не опубликованы на хосте | Проверка снаружи `curl https://<домен>/metrics` → SPA/404 | Caddy проксирует только `/api/*`; наружу опубликованы только 80/443 | Реализовано |
| NFR-SEC-10 | Секреты не попадают в репозиторий и образы | Секреты — только в `.env` на сервере и в GitHub Secrets; в репозитории — `.env.example` с заглушками | Сканер секретов в CI (gitleaks) | Процесс соблюдается; сканера нет | Реализовано |
| NFR-SEC-11 | Минимальные привилегии контейнеров | Бэкенд: read-only FS, `tmpfs /tmp` с `noexec,nosuid`, `cap_drop: ALL`, `no-new-privileges`, непривилегированный пользователь | `docker inspect`; Trivy для образов | Как в требовании (пользователь — проверить в `Dockerfile`) | Реализовано |
| NFR-SEC-12 | Логи не содержат секретов и содержимого резюме | Тела запросов и ответов не логируются; заголовки авторизации и cookie не логируются | Ревью `middleware/logger.go` | Как в требовании | Реализовано |

## Персональные данные (NFR-PRV)

Сервис обрабатывает персональные данные кандидатов (ФИО, дата рождения, фото, контакты, опыт) и технические данные посетителей (IP, User-Agent). Применяется 152-ФЗ «О персональных данных».

| ID | Требование | Метрика и цель | Проверка | Сейчас | Статус |
|---|---|---|---|---|---|
| NFR-PRV-01 | Локализация данных | Базы данных, бэкапы и логи с ПДн граждан РФ хранятся на серверах в РФ | Договор с хостингом, схема инфраструктуры | Зависит от выбранного сервера; не зафиксировано | Частично |
| NFR-PRV-02 | Правовая база и прозрачность | Опубликованы политика обработки ПДн и пользовательское соглашение; кандидат принимает их при регистрации; посетитель публичной страницы видит уведомление о статистике ([FR-ANL-050](../03-functional/FR-ANL.md)) | Юридическое ревью | Документов нет | План |
| NFR-PRV-03 | Минимизация данных посетителей | IP хранится только как HMAC-SHA256 с суточной солью; User-Agent — только категории устройства, браузера и ОС; referrer — только хост; нет fingerprinting и сторонних счётчиков | Ревью схемы `resume_link_views`; тест, что сырой IP не попадает в БД | Текущие события содержат только ссылку, тип и время; новая аналитика — по проекту | Частично |
| NFR-PRV-04 | Право на удаление | Удаление аккаунта удаляет данные из основной БД сразу, из бэкапов — по истечении их ретенции (≤ 35 дней) | Интеграционный тест каскада; описание процедуры | Удаления аккаунта нет | План |
| NFR-PRV-05 | Сроки хранения | Визиты аналитики — 12 месяцев, клики — 90 дней, журналы доступа с IP — 30 дней; удаление автоматическое | Ночная задача очистки; проверка ретенции логов | Ретенции нет | План |
| NFR-PRV-06 | Публикация — осознанное действие кандидата | Резюме видно посетителям только после явного «Опубликовать»; скрытые контакты не раскрываются без действия посетителя | FR-RES-023, FR-CNT-003 | Технически — так; юридически оформленного согласия нет (NFR-PRV-02) | Частично |
| NFR-PRV-07 | Персональные данные в логах | `client_ip` в журналах — ПДн: доступ к логам только у оператора, хранение ≤ 30 дней | Настройки сборщика логов | Логи — stdout контейнера, ретенция по умолчанию Docker | План |
