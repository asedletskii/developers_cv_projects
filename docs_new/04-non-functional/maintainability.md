# Сопровождаемость (NFR-MNT)

| ID | Требование | Метрика и цель | Проверка | Сейчас | Статус |
|---|---|---|---|---|---|
| NFR-MNT-01 | Модульная архитектура бэкенда | Модульный монолит: модули `user`, `resume`, `resume_link`; внутри — слои `domain` → `application` (commands/queries, ports) → `infrastructure` / `transport`. Домен не импортирует инфраструктуру и транспорт; модули общаются через порты. Сборка зависимостей — Wire | Тест `internal/architecture/imports_test.go` проверяет запреты импортов между слоями модуля `resume` | Как в требовании; для `user` и `resume_link` архитектурный тест не написан | Частично |
| NFR-MNT-02 | Единые правила фронтенда | Структура и именование компонентов по [README](../../README.md#структура-и-правила) и [STYLEGUIDE](../../frontend/STYLEGUIDE.md); конечные наборы — `enum`; утилиты — отдельно с тестом рядом | ESLint, Prettier, ревью | Как в требовании | Реализовано |
| NFR-MNT-03 | Обязательные проверки перед мержем | Мерж в `main` только при зелёном CI (FR-OPS-001) и одобренном ревью | Branch protection в GitHub | CI есть; обязательность проверок и ревью — проверить в настройках репозитория | Частично |
| NFR-MNT-04 | Тесты на критичную логику | Домен и валидаторы: покрытие строк ≥ **80 %**; каждая ручка — интеграционный тест на реальном PostgreSQL (testcontainers) для успеха, валидации, владения и конфликта версий; утилиты фронта — Jest | `go test -cover`, отчёт в CI | Тесты домена, ручек и интеграционные на testcontainers есть; покрытие не измеряется и не ограничивается | Частично |
| NFR-MNT-05 | Безопасные миграции | Миграции только вперёд, у каждой есть `down`; схема совместима с предыдущей версией кода (expand → deploy → contract), чтобы откат образа не ломал работу | Ревью миграций; тест `up → down → up` в CI | `up`/`down` есть; проверки совместимости и прогонов нет | Частично |
| NFR-MNT-06 | Документация живёт с кодом | PR, меняющий поведение, обновляет `docs_new` (статус требования, трассировку) и `docs/api` | Чек-лист в шаблоне PR | Процесс вводится этим документом | План |
| NFR-MNT-07 | Воспроизводимые сборки и версии | Зависимости зафиксированы lock-файлами (`go.sum`, `yarn.lock`); образы сторонних сервисов — с конкретной версией, без `latest` | Ревью compose-файлов | Lock-файлы есть; `minio:latest` не зафиксирован ([GAP-08](../06-gaps-and-risks.md#технический-долг)) | Частично |
| NFR-MNT-08 | Конфигурация проверяется на старте | Все параметры — из переменных окружения; некорректные значения и небезопасные для прода настройки останавливают запуск с понятной ошибкой | Тесты `config_test.go` | Так: `validate`, `validateProductionSecurity` | Реализовано |
| NFR-MNT-09 | Быстрый старт для разработчика | Бэкенд — `make compose-up && make run`, фронтенд — `yarn install && yarn start` (прокси Vite на API); время от клона до работающего стенда ≤ 15 минут | Проверка новым участником | Так | Реализовано |
