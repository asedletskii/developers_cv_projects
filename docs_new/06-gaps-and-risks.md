# Расхождения, технический долг, риски

Состояние на `main` 2026-09-30. Каждый пункт закрывается отдельной задачей; после исправления строка переносится в раздел «Закрыто» с номером PR.

## Расхождения

Места, где фронтенд, бэкенд и документация описывают разное поведение.

| ID | Что расходится | Где | Последствие | Как исправить | Требования |
|---|---|---|---|---|---|
| GAP-01 | Большая часть `docs/api` описывает старый контракт: `POST`/`PUT`/`DELETE` по отдельным записям, `GET` секций, `PUT …/order`, уникальность языка резюме у пользователя. Публичный `GET` теперь описан как `/cv/:linkId`; другие разделы API требуют отдельной сверки. Сейчас секции заменяются целиком `PUT` с `version` и `items`, публичный доступ — только по ссылке, резюме на одном языке может быть несколько | `docs/api/*.md` | Новый участник или внешний клиент реализует несуществующий контракт | Сверить оставшиеся `docs/api` разделы с кодом либо заменить ссылками на [FR](03-functional/README.md) | FR-EDT-001, FR-PUB-001, FR-RES-005 |
| GAP-02 | Фронт переименовывает ссылку через `PUT /lk/link/:linkId` с `{ name }`, на бэке маршрута нет | `curriculumVitae.api.ts` (`renameResumeLink`), `resume_link/transport/http/handler.go` | «Переименовать» в интерфейсе всегда падает с `404` | Добавить команду и ручку `PUT /lk/link/:linkId` с `{ version, name }`; фронт — передавать версию | FR-LNK-010, US-LNK-04 |
| GAP-03 | Кабинет открывается по адресу `/cv/lk/:userId`, и фронт подставляет этот `userId` в `X-Mock-User-ID` | `ROUTES.lkProfile`, `ownerHeaders` | Любой, кто знает UUID пользователя, читает и меняет его резюме | Закрывается вместе с настоящей аутентификацией; адрес кабинета — без `userId` | FR-ACC-003, NFR-SEC-03 |
| GAP-04 | Разный формат ошибок: `412` у резюме и секций — без тела; `400` у `PUT /resume/:id/status` при `version < 1` — `{"error": "version must be positive"}` строкой; у ссылок `412` — со стандартным телом | `resume/transport/http/*`, `resume_handler.go` | Клиент не может единообразно разбирать ошибки; нет `requestId` для поддержки | Отдавать все ошибки через `apperrors.WriteError` с кодом `PRECONDITION_FAILED` | FR-API-009, FR-API-010 |
| GAP-05 | Бэк отвечает `412` при конфликте версий, фронт показывает общий «Не удалось сохранить резюме» | `saveResumeSection`, экран редактора | Пользователь не понимает, что делать; может потерять изменения при перезагрузке | Отдельный текст и действие «Обновить» с сохранением введённого в форме | FR-RES-062, US-RES-07 |
| GAP-06 | Бэк хранит у проекта роль, скриншоты, ссылку на код и участников; форма их не редактирует, публичная проекция не отдаёт | `ProjectsEditor`, `queries.ToPublic` | Поля заполняются только через API и нигде не видны | Добавить поля в форму и в публичную проекцию либо убрать из модели | FR-EDT-103, FR-EDT-104 |
| GAP-07 | `HTTP_TRUSTED_PROXIES` пуст в `.env.example`, а бэкенд стоит за Caddy | `.env.example`, `router.go` | `ClientIP()` возвращает адрес Caddy: рейт-лимит общий на всех посетителей, в логах один IP; будущая аналитика по IP не работает | Указать подсеть docker-сети Caddy; проверять в `validateProductionSecurity` | FR-API-020, NFR-SEC-06 |
| GAP-09 | `PUT /lk/profile` разбирает тело нестрогим `ShouldBindJSON`: неизвестные поля молча игнорируются | `user/transport/http/profile/handler.go` | Опечатка в имени поля у клиента не видна, данные теряются | Использовать общий `jsonhttp.BindJSON` | FR-API-004 |
| GAP-10 | Фронт называет параметр публичных маршрутов API `resumeId` (`/cv/:resumeId`, `/cv/:resumeId/contact-views`), хотя это `linkId` | `constants/apiRoutes.ts`, `curriculumVitae.api.ts` | Путаница при чтении кода; комментарий `getResumeLinkUrl` допускает id резюме, который бэк не принимает | Переименовать в `linkId` | FR-PUB-001 |
| GAP-11 | Статистика ссылки есть на бэке, интерфейс её не показывает; счётчик включает перезагрузки и визиты владельца | `GET /lk/link/:id/statistics`, `AnalyticsTab` | Функция «по ссылке можно считать просмотры», обещанная в подсказке вкладки «Ссылки», пользователю недоступна | Этап 1 [аналитики](../docs/analytics/README.md#этапы) | FR-LNK-030, FR-ANL-010 |
| GAP-12 | HSTS выставляет бэкенд только при `HTTP_TLS_ENABLED=true`; в проде TLS терминирует Caddy, флаг выключен | `middleware/security.go`, `Caddyfile` | Нет HSTS ни на статике, ни на API — возможен downgrade при первом заходе | Добавить `header Strict-Transport-Security` и CSP в `Caddyfile` | NFR-SEC-04, NFR-SEC-05 |
| GAP-13 | Mock-аутентификатор подключён безусловно и используется в проде | `app/wire.go`, `app/data_source.go` | См. RISK-01 | Выбор аутентификатора по конфигу; запрет mock в `production` | NFR-SEC-02 |

## Технический долг

| ID | Долг | Влияние | Предложение |
|---|---|---|---|
| GAP-08 | MinIO и NATS подняты в проде, но бэкенд их не использует; `minio:latest` не зафиксирован по версии | Лишние ресурсы и поверхность атаки; непредсказуемые обновления MinIO | Убрать из `docker-compose.prod.yml` до появления потребителя (загрузка фото — MinIO, уведомления — пока outbox в PostgreSQL); при возврате — закрепить версии |
| GAP-14 | Нет ограничений длины текстовых полей и числа записей в секциях | Резюме на 1 МиБ JSON; тяжёлые страницы; поле для злоупотреблений | FR-EDT-118, FR-EDT-119, FR-RES-008 |
| GAP-15 | Ответы `PUT` не возвращают новую версию; клиент либо перечитывает резюме целиком, либо сам прибавляет 1 | Лишний трафик; хрупкая логика на клиенте | Возвращать `ETag` / заголовок `X-Resume-Version` |
| GAP-16 | Ошибка валидации секции — общий `400 "Invalid request"` без поля и причины | Интерфейс не может подсветить конкретное поле | Добавить в тело ошибки `details: [{ field, reason }]` |
| GAP-17 | Публичная проекция и кабинетное представление имеют разную форму (`experience`/`experiences`, `stack`/`technologies`, плоский профиль) | Два набора типов и нормализаторов на фронте | [План унификации](../docs/api/unification-plan.md) |
| GAP-18 | Фото, скриншоты, файл резюме — внешние ссылки, которые браузер посетителя загружает напрямую со стороннего хоста | Битые изображения при удалении файла; сторонний хост видит IP посетителей и может служить трекинг-пикселем | Загрузка файлов в MinIO с отдачей через свой домен (идея) |
| GAP-19 | Нет e2e-тестов пользовательских сценариев | Регрессии интерфейса ловятся вручную | Playwright на ключевые истории (создать → заполнить → опубликовать → ссылка → открыть → раскрыть контакт) |
| GAP-20 | Архитектурный тест импортов покрывает только модуль `resume` | Нарушения слоёв в `user` и `resume_link` не ловятся | Расширить `architecture/imports_test.go` |

## Реестр рисков

Оценка: вероятность и влияние — Н (низкая), С (средняя), В (высокая); критичность = максимум с учётом обоих.

| ID | Риск | Вероятность | Влияние | Критичность | Меры | Владелец | Требования |
|---|---|---|---|---|---|---|---|
| RISK-01 | **Нет аутентификации.** Любой, кто знает UUID пользователя, читает и меняет его резюме через заголовок `X-Mock-User-ID` | В | В | **Критично** | Не запускать публично до FR-ACC-002; до этого — закрыть кабинет на уровне Caddy (basic auth или allowlist IP) | Разработка | FR-ACC-002, NFR-SEC-01, NFR-SEC-02 |
| RISK-02 | **Нет бэкапов.** Отказ диска или ошибочная миграция уничтожают все данные | С | В | **Высокая** | FR-OPS-020 до публичного запуска; перед каждой миграцией с `DROP` — ручной дамп | Эксплуатация | NFR-REL-04 |
| RISK-03 | **Несоответствие 152-ФЗ**: нет политики обработки ПДн, согласий, процедуры удаления, локализация не зафиксирована | С | В | **Высокая** | NFR-PRV-01 – NFR-PRV-05 до публичного запуска; юридическое ревью | Продукт | NFR-PRV-* |
| RISK-04 | Массовый сбор скрытых контактов через ручку раскрытия | С | С | Средняя | FR-CNT-015, FR-CNT-016; мониторинг числа раскрытий | Разработка | FR-CNT-015 |
| RISK-05 | За прокси все клиенты делят один рейт-лимит: один активный пользователь или бот вызывает `429` у всех | В | С | **Высокая** | GAP-07 | Эксплуатация | NFR-SEC-06 |
| RISK-06 | Кандидаты перестают доверять аналитике из-за накруток (перезагрузки, свои визиты, боты) | В (при запуске текущих счётчиков) | С | Средняя | Не показывать сырые счётчики; выпускать аналитику сразу с фильтрацией (этап 1) | Продукт | FR-ANL-003, FR-ANL-004 |
| RISK-07 | Единственный инстанс и сервер — единая точка отказа | С | С | Средняя | SLO 99,5 % это допускает; бэкапы (RISK-02) и документированное восстановление на новый сервер ≤ RTO | Эксплуатация | NFR-REL-01, NFR-REL-04 |
| RISK-08 | Пользовательские цвета дают нечитаемую страницу (низкий контраст) | С | Н | Низкая | FR-DSG-004 | Разработка | NFR-UX-04 |
| RISK-09 | Внешние ссылки на фото и файлы ломаются или отслеживают посетителей | С | Н | Низкая | GAP-18 | Продукт | — |
| RISK-10 | Bus factor 1: знание системы у одного разработчика | В | С | Средняя | Эта документация; ADR на ключевые решения; e2e-тесты | Команда | NFR-MNT-06 |
