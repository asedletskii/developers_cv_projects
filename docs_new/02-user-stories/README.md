# Пользовательские истории

## Формат

```
### US-<ДОМЕН>-<NN>. <Короткое название>

Приоритет · Статус · Персона

Как <роль>, я хочу <действие>, чтобы <ценность>.

Критерии приёмки
  Сценарий: <название>
    Дано <начальное состояние>
    Когда <действие>
    Тогда <наблюдаемый результат>

Требования: FR-…, NFR-…
```

Критерии приёмки описывают **наблюдаемое поведение** (что видит пользователь или что отвечает API), а не реализацию. Каждый сценарий должен превращаться в e2e- или интеграционный тест без домыслов.

Определение готовности (DoD) для любой истории:

1. Все сценарии приёмки проходят на стенде.
2. Связанные FR реализованы, их статус обновлён в [трассировке](../05-traceability.md).
3. Бэкенд: юнит-тесты домена и интеграционный тест ручки; фронтенд: Jest-тесты утилит и хуков.
4. Тексты интерфейса есть на `ru` и `en`.
5. Не нарушены NFR: особенно [безопасность](../04-non-functional/security-privacy.md) и [UX](../04-non-functional/ux-compatibility.md).
6. Документация (`docs_new`, `docs/api`) обновлена в том же PR.
