# Аналитика ссылок: фронтенд

Общая картина и термины — в [README](README.md), контракты ручек — в [бэкенде](backend.md#ручки). Здесь две части: трекер на публичной странице (`CurriculumVitaeScreen`) и вкладка «Аналитика» в кабинете (`AnalyticsTab` на `LkResumeEditScreen`).

Все новые файлы раскладываются по правилам из корневого README: утилиты — в `features/curriculumVitae/utils/<name>/` с тестом рядом, хуки — в `hooks/`, конечные наборы — `enum` в `types/enums.ts`.

## Часть 1. Трекер на публичной странице

### Жизненный цикл

1. `usePublicResume` вызывает `getPublicResume`. API-метод начинает возвращать `{ resume, viewId }`, где `viewId` берётся из заголовка ответа `X-View-Id` (может отсутствовать — тогда трекер выключен).
2. `CurriculumVitaeScreen` оборачивает страницу в `AnalyticsProvider` с `linkId` и `viewId`.
3. Провайдер создаёт один экземпляр трекера (чистый класс или замыкание в `utils/createAnalyticsTracker`, без React — так его проще тестировать) и отдаёт через контекст хук `useAnalytics()` с методом `track(event)`.
4. Трекер копит события в очереди и отправляет их батчем в `POST /api/v1/cv/:linkId/events`.

Если `viewId` нет (ошибка записи на бэке, предпросмотр в кабинете `LkResumeScreen`, выключенная ссылка — `410`), провайдер отдаёт no-op трекер. Компоненты вызывают `track` всегда, не проверяя, включена ли аналитика.

**Предпросмотр в кабинете не трекается никогда.** `LkResumeScreen` рендерит те же секции, но без `AnalyticsProvider`, и контекст по умолчанию — no-op.

### Что собирается

| Сигнал | Откуда | Как |
|---|---|---|
| **Активное время** | `document.visibilityState` | Таймер тикает, только пока вкладка видима. Уходит в `state.activeMs` (накопительно). |
| **Дочитывание** | `IntersectionObserver` на корне каждой `Section` | Секция считается просмотренной, если ≥ 40 % её высоты (или ≥ 50 % viewport для высоких секций) видно ≥ 1 с. Один раз за визит на секцию — событие `section_view`. Самая дальняя по порядку — `state.maxSection`. |
| **Точка ухода** | тот же observer | Секция, занимающая большую часть viewport в момент последнего флаша, — `state.exitSection`. |
| **Печать** | `window` | `beforeprint` → `track({ type: Print })`, на `afterprint` сразу `flush()` (после диалога вкладку часто закрывают). Повтор в пределах 2 с трекер отбрасывает сам. Захватывает и Ctrl+P, и «сохранить как PDF» из меню браузера. |
| **Копирование контакта** | `useContactButton` | После успешной записи в буфер → `track({ type: ContactCopy, contact })`. |
| **Переход по контакту** | `ContactButton` | `onClick` по раскрытой (или открытой) ссылке Telegram, почты, телефона → `track({ type: ContactClick, contact })`. Ссылка не перехватывается. |
| **Скачивание** | `ResumeButton`, `Cta` | Резюме собирается в HTML на странице (`useDownloadResume`): скрытые контакты запрашиваются одним запросом с Turnstile (`initiator: download`), после сохранения файла → `track({ type: Download })`. Файла автора (`resumeLink`) больше нет. |
| **Фильтр технологий** | `TechnologyFilterProvider` / `useTechnologyFilter` | При выборе и сбросе → `track({ type: TechFilter, technology, action })`. Дебаунс не нужен — это дискретные клики. |
| **Внешние ссылки** | `ExternalLink`, ссылки проектов и git | `track({ type: ExternalClick, kind, target: hostname })`. Полный URL не шлём. |
| **Раскрытие контакта** | `ContactsSection` → `viewContact` | Шлётся не трекером, а существующей ручкой `contact-views`: добавить в тело `viewId`. |
| **Клики** (этап 4) | делегированный `pointerdown` на корне страницы | См. ниже. |

Скролл в процентах **не** собираем: высота страницы зависит от ширины экрана и раскрытых секций, поэтому «60 %» на мобильном и на десктопе — разные вещи. Секции дают сравнимый сигнал.

### Отправка

- **Периодический флаш:** раз в 15 с, если есть что отправлять (новые события или `activeMs` вырос). Нужен потому, что мобильный Safari часто не шлёт ничего при закрытии вкладки — без периодики мы бы потеряли самые интересные визиты.
- **Флаш при уходе:** на `visibilitychange` → `hidden` и на `pagehide`, с `final: true` на `pagehide`. `beforeunload` не использовать: он ломает bfcache и ненадёжен на мобильных.
- **Транспорт:** `navigator.sendBeacon(url, JSON.stringify(batch))` — строка уходит как `text/plain`, без preflight, бэк это принимает. Если `sendBeacon` вернул `false` или его нет — `fetch(url, { method: 'POST', body, keepalive: true })`. Через axios не шлём: он не умеет `keepalive`.
- **Идемпотентность:** у каждого события `id = crypto.randomUUID()`, батч несёт растущий `seq`. Очередь очищается сразу после вызова `sendBeacon` (ответа всё равно нет); повторов не делаем. Дубли, если они случатся, отсекает бэк.
- **Лимиты:** не больше 100 событий в батче, лишнее уходит следующим. Тело > 32 КБ не отправляется.
- **Возврат на вкладку** после `hidden` продолжает тот же визит (тот же `viewId`), таймер снова тикает.
- **bfcache:** на `pageshow` с `persisted === true` визит продолжается, новый `viewId` не запрашивается.

### Click-map (этап 4)

Один делегированный обработчик `pointerdown` на корне `CurriculumVitae`:

1. `event.target.closest('[data-section-id]')` → секция (атрибут добавить на корень `Section`). Клик вне секций игнорируется.
2. Координаты относительно прямоугольника секции: `x = (clientX - rect.left) / rect.width * 10000`, `y = (clientY - rect.top) / rect.height * 10000`, округлить до целого.
3. `target` — ближайший `[data-analytics-id]`, если есть (кнопки контактов, ссылки проектов, фильтр), иначе пусто.
4. `vw = window.innerWidth`.
5. В очередь `clicks` трекера; отправка тем же батчем.

Троттлинг: не больше 1 клика в 100 мс и 200 кликов на визит.

### Раскладка и порядок секций

Трекер ничего не знает про порядок секций и версии: `section_view` несёт только id секции, а клик — `section`, проценты внутри неё и `vw`. Снимок раскладки (`layout.order`, `layout_hash`) сервер делает сам при `GET /cv/:linkId`, подробности — в [бэкенде](backend.md#снимок-раскладки).

### Владелец на своей странице

Фронту делать ничего не нужно. Сессия — httpOnly cookie `__Host-session` с `Path=/`; публичный `GET /api/v1/cv/:linkId` идёт на тот же origin, и браузер отправляет cookie сам (`withCredentials: true` в `axios.config.ts` нужен только для нестандартного `VITE_API_BASE_URL`). Пометку `owner` ставит бэк.

- В dev-режиме с `AUTH_MODE=mock` axios добавляет `X-Mock-User-ID` из `VITE_MOCK_USER_ID` ко всем запросам, включая публичные, — пометка `owner` работает и локально.
- `sendBeacon` и `fetch(…, { keepalive: true })` на тот же origin тоже несут cookie, но ручке батча сессия не нужна: визит уже помечен при `GET`.
- Публичный `401` невозможен: публичные ручки не требуют сессии. Перехватчик `401` в `axios.config.ts` (`sessionExpired`) на них не сработает и вход не потребует.

## Часть 2. Вкладка «Аналитика» в кабинете

### Структура экрана

`AnalyticsTab` получает `linksState` (как `LinksTab`) и `resumeId`.

```
AnalyticsTab/
  AnalyticsTab.tsx      ← выбор ссылки + раскладка
  LinkPicker.tsx        ← «Все ссылки» | конкретная ссылка
  PeriodPicker.tsx      ← 7 / 30 / 90 дней
  Summary.tsx           ← плашки с числами
  DailyChart.tsx        ← столбики по дням
  VisitFeed.tsx         ← лента визитов
  Visit.tsx             ← одна карточка визита
  SectionFunnel.tsx     ← дочитывание по секциям (этап 2)
  TechnologyInterest.tsx (этап 2)
  ClickMap.tsx          (этап 4)
  hooks/useAnalytics*.ts
  index.ts
```

Сверху вниз по важности:

1. **Шапка:** выбор ссылки (по умолчанию «Все ссылки» → `GET /lk/resume/:id/statistics`) и период.
2. **Плашки:** открытия · прочтения · уникальные посетители · раскрытия контактов · скачивания. Под числами — «первый просмотр 12 сен, последний вчера в 16:40». Мелким шрифтом: «Отфильтровано: ботов 5, ваших просмотров 3» — это доверие к цифрам.
3. **Лента визитов** — главный блок. Карточка визита:
   > **Вчера, 16:40** · мобильный, iOS Safari · из Telegram · **2 мин 11 с**
   > Посетитель №2 (заходил раньше) · дошёл до «Опыта», ушёл на «Проектах»
   > 16:41 раскрыл Telegram · 16:41 фильтр «Go»

   Визит без прочтения показывается приглушённо: «открыл и закрыл». Кнопка «Показать ещё» — курсор `nextCursor`.
4. **График по дням:** столбики «открытия» с наложением «прочтений». При < 3 открытий за период график скрыт — пустая сетка из нулей ничего не говорит. Под заголовком — пиковый день.

Всё ниже в этом пункте считается на фронте из тех же ответов, отдельные ручки не нужны:

- **Сравнение с предыдущим периодом** на плашках (`▲ +30 %` / `▼ 12 %`): второй запрос тех же ручек с периодом вплотную перед текущим. Если прошлый период пуст — стрелки нет (процент от нуля ничего не значит). Запрос необязательный: при ошибке отчёт показывается без сравнения.
- **Производные метрики:** доля прочтений (прочтения / открытия), медианное время, «вернулись N из M», доля читателей, раскрывших контакт.
- **По дням недели:** группировка `statistics/daily` по дню недели (понедельник первый) и «чаще всего открывают в такой день».
- **Проценты** в блоках «Устройства» и «Откуда пришли», доля от прочтений в воронке по секциям.
- **Лента визитов:** фильтры «все / прочитанные / с действиями» (по уже загруженным визитам), переключатель «показать ботов и мои визиты» (`includeFiltered=true`; у таких визитов метка `traffic`), в раскрытом визите — число визитов этого посетителя в загруженной ленте.
- **Карта кликов:** под заголовком три секции с наибольшим числом кликов (из сумм `total` по сеткам).
5. **Дочитывание** (этап 2): горизонтальная воронка по секциям в порядке страницы — сколько прочтений дошло до секции и сколько на ней закончилось.
6. **Интерес к стеку** (этап 2): список технологий с числом выборов в фильтре.
7. **Click-map** (этап 4): отдельный режим, см. ниже.

Пустое состояние: у резюме нет ссылок → переиспользовать `CreateLinkPrompt`; ссылки есть, визитов нет → «Пока никто не открывал. Отправьте ссылку — здесь появятся просмотры».

Ссылки в `LinksTab` получают счётчик рядом с названием («12 · 7 прочт.») из `GET /lk/resume/:id/statistics` → `links[]` — одним запросом на всю вкладку, а не по запросу на каждую ссылку.

### Данные

- Хуки по образцу `useResumeLinks`: `useLinkStatistics(scope, period)`, `useLinkDaily`, `useLinkVisits` (накопительная пагинация), `useLinkSections`. `AbortController` на смену ссылки или периода.
- `tz` в запросах — `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- Даты и относительное время («вчера в 16:40») — через i18next и `Intl.RelativeTimeFormat`, утилита `formatVisitTime` в `utils/` с тестом.
- Словари — `Lk.Analytics` в `locale/lk.dict.ts` (ru/en). Названия секций берутся из существующих ключей секций, а не дублируются.
- Автообновления нет. Кнопка «Обновить» в шапке, плюс перезапрос при возврате на вкладку (`visibilitychange`).

### Графики

Библиотеку не добавляем: столбики по дням (≤ 90) и воронка по секциям (≤ 9) — это десяток `<rect>` в SVG. Компонент `DailyChart` на чистом SVG, цвета — из темы MUI (`palette.primary` для прочтений, его светлый оттенок для открытий), подписи осей — даты через `Intl`. Тултип по наведению и тапу.

### Click-map (этап 4)

- Карта по умолчанию строится только по кликам на *актуальную* версию секции (`layout_hash`). Если часть кликов пришла на прошлые версии, под картой строка «ещё N кликов по прежней версии секции не показаны» и переключатель «Показать и их» (`includeStale=true`) с пометкой, что положение может быть неточным.
- Режим «Карта кликов» открывает предпросмотр резюме (те же компоненты, что в `LkResumeScreen`) с переключателем брейкпоинта `xs / md / lg` — ширина контейнера фиксируется под брейкпоинт, чтобы сетка совпала.
- Для каждой секции `GET /lk/link/:linkId/clicks?section&breakpoint` → сетка 20×20 → `<canvas>` поверх корня секции (`position: absolute`, `pointer-events: none`), ячейки с прозрачностью по `count / max`.
- Своего рисования хватит. `heatmap.js`, упомянутый в TODO, даёт размытую «тепловую» картинку, но для сетки 20×20 это одна зависимость ради красоты; решение можно принять на этапе 4.

## Приватность на стороне клиента

- Трекер не читает и не шлёт содержимое полей, текст выделения, URL целиком, `localStorage` посетителя.
- Никаких сторонних скриптов (Метрика, GA): аналитика только своя, через тот же origin.
- **Уведомление о статистике.** Не в футере, а плашка справа снизу (`AnalyticsNotice`): оформлена как диалог приложения, но без затемнения и без закрытия по клику вне окна — исчезает только по кнопке «Понятно», выбор хранится в `localStorage` (если он недоступен, плашка просто покажется снова). Показывается, только когда трекер реально работает (есть `viewId`), поэтому в предпросмотре кабинета её нет. Скрыта при печати (`data-print-hidden`). Текст — в словаре, см. [бэкенд](backend.md#приватность).
- **«Не отслеживать».** Если браузер шлёт `Do Not Track: 1` или Global Privacy Control, клиентский трекер не запускается и плашка не показывается (настройка `RESPECT_DO_NOT_TRACK` в серверном `.env`: фронтенд читает её из `/config.js`, который контейнер пишет при старте — меняется перезапуском контейнера `frontend`, без пересборки). Сам факт открытия страницы сервер всё равно считает — это серверный `view` без времени, кликов и действий.

## Обновление данных

Отчёт перезапрашивается кнопкой «Обновить» и автоматически — при возврате на вкладку после перерыва от минуты (`useRefreshOnFocus`); короткие переключения вкладок не считаются, чтобы цифры не мигали. Так же обновляется сводка на «Главной» и счётчики у ссылок.

## Тестирование

- `createAnalyticsTracker`: Jest с фейковыми таймерами — периодический флаш, `activeMs` не растёт при `hidden`, `final` на `pagehide`, лимит 100 событий, fallback на `fetch` без `sendBeacon`, no-op без `viewId`.
- Дочитывание: мок `IntersectionObserver`, порог в 1 с, одно `section_view` на секцию.
- `formatVisitTime`, `buildVisitSummary` (строка «дошёл до … ушёл на …») — юнит-тесты в `utils/`.
- `AnalyticsTab`: пустые состояния, скрытие графика при < 3 открытий, пагинация ленты.
