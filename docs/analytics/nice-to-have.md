# Аналитика ссылок: nice to have

Идеи поверх основных этапов ([README](README.md#этапы)). Каждая опирается на уже спроектированные сущности — визит (`resume_link_views`), события (`resume_link_events`), батч `POST /cv/:linkId/events` и outbox уведомлений — и не требует новой инфраструктуры, кроме отмеченного.

Порядок — по соотношению пользы и стоимости. Метка **[дёшево]** — несколько полей или новый тип события.

## 1. Кто смотрит

### 1.1. Организация по IP [дёшево]

Самый сильный сигнал: «визит из сети Яндекса».

**Бэкенд.**
- При записи визита, **до** хеширования IP, ищем его в офлайн-базе ASN (MaxMind GeoLite2 ASN, файл `.mmdb` ~10 МБ; ридер `github.com/oschwald/maxminddb-golang`). Сетевых запросов на визит нет.
- Новые поля визита:
  ```sql
  ALTER TABLE resume_link_views
      ADD COLUMN network_org  text,     -- «YANDEX LLC», NULL для домашних сетей
      ADD COLUMN network_kind text NOT NULL DEFAULT 'unknown'
          CHECK (network_kind IN ('corporate','isp','hosting','mobile','unknown'));
  ```
- `network_kind` — по списку крупных провайдеров (`isp`, `mobile`) и хостингов (`hosting` — AWS, Hetzner, Selectel…). Всё остальное с известным `org` считаем `corporate`. Для `isp`/`mobile` название сети **не сохраняем**: «Ростелеком» ничего не говорит, но сужает круг до человека.
- `hosting` — дополнительный признак бота: браузер из дата-центра почти всегда сканер или VPN. Классификатор ставит `traffic = 'suspect'`, `traffic_reason = 'hosting'`, если нет других признаков человека (прочтение этот флаг снимает).
- Обновление базы: `.mmdb` монтируется томом, раз в месяц подтягивается скриптом на сервере (лицензионный ключ MaxMind — в `.env`). Если файла нет, фича тихо выключена.

**Фронтенд.** В карточке визита — «из сети YANDEX LLC» (с человекочитаемой нормализацией: словарь `org → название` для топ-50 компаний, остальное как есть). В сводке — блок «Компании»: список `network_org` с числом посетителей.

**Ограничения.** Удалёнка и VPN: рекрутер из дома покажется «домашним провайдером». Корпоративный прокси крупной компании бывает зарегистрирован на облако — тогда это `hosting`. Сигнал вероятностный, в интерфейсе подаётся как «вероятно, из сети …».

### 1.2. Город и страна [дёшево]

GeoLite2 City тем же ридером, поля `country` (ISO-код) и `city`. Точность по мобильным сетям — область, не город; в интерфейсе показываем страну всегда, город — только если `network_kind = 'corporate'` или `isp`.

### 1.3. Язык браузера [дёшево]

Первый язык из `Accept-Language` → поле `browser_language` (`ru`, `en`, …). В карточке — «браузер на английском». Если резюме открыто на русском, а язык браузера не `ru` — подсказка владельцу: «возможно, стоит отправить EN-версию».

### 1.4. «Ссылку переслали» [дёшево]

Правило, вычисляемое при записи визита: по ссылке уже есть посетитель A, приходит новый посетитель B, и выполняется хотя бы одно:
- у B и A одинаковый `network_org` (резюме ходит внутри компании);
- B пришёл через ≥ 1 ч после первого визита A (не один человек с двух устройств в ту же минуту).

Событие `forwarded` с `payload: { "sameOrg": true }`, уведомление `link_forwarded` в outbox: «Резюме переслали: второй человек из сети Яндекса открыл ссылку „Яндекс, Go“». Дедуп — `link_forwarded:<link_id>:<visitor_id>`.

В сводке ссылки — «Посетителей: 3 (переслано 2 раза)».

### 1.5. Один человек, разные ссылки

Cookie посетителя (`__Secure-cv_vid`) уже общая для всех ссылок (`Path=/api/v1/cv`). В ленте визитов: «Этот посетитель также открывал ссылку „Озон“». Ручка ленты отдаёт `visitor.otherLinks: [{ id, name }]` — только ссылки того же владельца. Интересно, когда один рекрутер работает на несколько компаний.

## 2. Как читает

### 2.1. Время на секцию

Вместо «дошёл / не дошёл» — сколько секция была в фокусе.

**Фронтенд.** Тот же `IntersectionObserver`: для секции, занимающей большую часть viewport, копится время, пока вкладка видима. Уходит в `state.sectionMs: { "experience": 41000, "projects": 12000 }`.

**Бэкенд.** Поле визита `section_ms jsonb`, применяется монотонно по ключам (`GREATEST` на каждое значение). Отчёт `statistics/sections` получает `medianMs` на секцию по прочтениям.

**Интерфейс.** В воронке дочитывания — вторая шкала «среднее время». В карточке визита — «больше всего времени: Опыт (41 с)».

### 2.2. Копирование текста [дёшево]

Сильный сигнал намерения: скопировали email, название компании, технологию.

**Фронтенд.** Слушатель `copy` на корне страницы. Отправляем событие `copy` с `payload: { section, kind, sample }`:
- `kind`: `contact` (выделение внутри блока контактов), `technology` (внутри `TechnologyList`), `text`;
- `sample` — первые 32 символа выделения **только** для `kind = technology`; для остальных не шлём текст вообще.

**Бэкенд.** Новый тип `copy` в `resume_link_events`. Для `kind = contact` — уведомление `contact_copied` (это практически «сейчас напишут»).

### 2.3. Печать и сохранение в PDF [дёшево]

`window.addEventListener('beforeprint', …)` → событие `print`. Уведомление: «Резюме распечатали — скорее всего, несут на обсуждение». Работает и для «Сохранить как PDF», так как это тот же диалог печати.

Стоит проверить печатную вёрстку (`data-print-hidden` уже есть в `ControlsBar`), раз её начнут считать.

### 2.4. Раскрытие деталей [дёшево]

- Развернули место работы (`useExpandableJobs`) → `expand` с `payload: { section: "experience", item: "<id записи>" }`.
- Открыли детали проекта → то же с `section: "projects"`.

Бэкенд хранит `item` как id, отчёт подставляет название (компания / проект) при чтении. В интерфейсе — «Интерес к опыту»: какие места работы разворачивали и сколько раз.

### 2.5. Переключения вкладок

Паттерн «сверяет с вакансией или с другими кандидатами»: много коротких уходов и возвратов.

**Фронтенд.** Счётчик переходов `hidden → visible` при условии, что отсутствие было < 2 мин. Уходит в `state.tabSwitches`.

**Бэкенд.** Поле визита `tab_switches smallint`. В карточке при ≥ 3 — «переключался между вкладками 5 раз — вероятно, сравнивал».

### 2.6. Время суток посетителя [дёшево]

**Фронтенд.** Первый батч несёт `state.tz` (IANA из `Intl`) и смещение.

**Бэкенд.** Поле визита `visitor_tz`. При отдаче ленты — локальное время посетителя и флаг `isWorkingHours` (будни 9–19). В карточке: «открыл в 22:10 по его времени».

### 2.7. Повторные визиты

Данные уже есть (`visitor_id`, `started_at`). Добавить в ленту: `visitor.visitNumber` («3-й визит») и `visitor.daysSinceFirst`. В сводке — «вернулись: 2 из 5, медиана до возврата — 3 дня». Уведомление `link_returned` на возврат через ≥ 1 сутки: частый признак подготовки к собеседованию.

## 3. Спросить напрямую

Самый точный источник, и он ничего не скрывает от посетителя.

### 3.1. Персональное приветствие на ссылку [дёшево]

Поле ссылки `greeting text NULL` (до 280 символов, ru/en не делим — ссылка и так под одного адресата). Отдаётся в публичном ответе `GET /cv/:linkId` полем `linkGreeting`, фронт показывает его вместо или поверх обычного `greeting` в `HeroSection`. Редактирование — в `LinkNameDialog` вторым полем.

### 3.2. Кнопка «Интересно»

Плавающая кнопка / блок в конце страницы: «Интересно, свяжитесь со мной».

- Форма: имя (необязательно), контакт (обязательно — email или Telegram), сообщение (необязательно).
- **Бэкенд:** `POST /api/v1/cv/:linkId/interest` → таблица `resume_link_leads (id, link_id, view_id, name, contact, message, created_at)`. Защита: рейт-лимит, honeypot-поле, минимальное время заполнения 3 с. Уведомление `lead` — всегда, без настроек.
- **Кабинет:** блок «Отклики» сверху вкладки аналитики.
- Вариант со слотами для созвона — отдельно и позже: либо своя сетка слотов в профиле, либо ссылка на внешний календарь (Cal.com, Calendly) с событием `booking_click`.

### 3.3. Вопрос при уходе

Не модалка: небольшая плашка внизу, появляется после прочтения (≥ 30 с активного времени и `maxSection` ≥ середины страницы), один раз на посетителя.

«Кандидат подходит?» → «Да / Нет / Нужно больше информации», опционально поле «Чего не хватило?».

`POST /api/v1/cv/:linkId/feedback` → событие `feedback` с `payload: { answer, comment }` (комментарий до 500 символов). Скрыть навсегда — в `localStorage` посетителя.

## 4. Сознательно не делаем

- **Fingerprinting** (canvas, audio, список шрифтов, WebGL) для узнавания посетителя без cookie. Серая зона по 152-ФЗ и прямое нарушение GDPR для EU-посетителей; Safari и Firefox его активно ломают; если рекрутер заметит — вред репутации кандидата больше пользы.
- **Деанонимизация личности**: сервисы «IP → сотрудник», сопоставление с соцсетями, трекинг-пиксели в письмах. Те же причины.
- **Запись сессии** (rrweb и аналоги). Тяжело по трафику и хранению, в запись попадает всё, включая ввод в форму отклика. Событий, времени по секциям и карты кликов для резюме достаточно.
- **Сторонние счётчики** (Метрика, GA) на публичной странице. Отдают данные посетителей третьей стороне и ломают тезис «обезличенная статистика только для владельца».
