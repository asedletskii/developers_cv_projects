# Владелец кабинета

Общие данные пользователя, чей кабинет открыт (левая колонка ЛК). Не относятся к конкретному резюме.
Фронтенд: `curriculumVitaeApi.getProfile` → `LkProfileScreen`, `ProfileCard`.

## `GET /lk/profile`

Профиль пользователя из заголовка `X-Mock-User-ID`. Тела нет.

**Ответ `200`**

| Поле | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `userId` | uuid | да | — | — |
| `name` | string | да | непустое | — |
| `surname` | string | да | непустое | — |
| `patronymic` | string | нет | поле отсутствует, если не задано | отсутствует |
| `position` | string | нет | — | отсутствует |
| `location` | string | нет | — | отсутствует |
| `photoPath` | string | нет | `http`/`https`-ссылка | отсутствует |

**Ошибки:** `401` — нет/неверен `X-Mock-User-ID`; `404` — у пользователя нет профиля.

**Создание.** Отдельной ручки создания пользователя в этом API нет: в рабочем сценарии пользователь создаётся auth-потоком. Чистая миграция не создаёт пользователей и профили; для локальной разработки предусмотрен отдельный необязательный seed (`make seed-dev` из `backend`). Это не то же самое, что профиль внутри резюме — см. [personal.md](personal.md).
