# Аналитика ссылок

Статистика просмотров резюме по именованным ссылкам (`/cv/:linkId`): публичная часть (выдача `viewId`, приём событий посетителя) и отчёты в кабинете.
Фронтенд: методы `curriculumVitaeApi` в [curriculumVitae.api.ts](../../frontend/src/features/curriculumVitae/api/curriculumVitae.api.ts), типы в [types/analytics.ts](../../frontend/src/features/curriculumVitae/types/analytics.ts), вкладка «Аналитика» (`AnalyticsTab`) и трекер на публичной странице (`useAnalyticsTracker`).

> **Статус: реализованный API-контракт.** Запросы и ответы описывают текущие backend-ручки и их frontend-клиентов. Устройство хранилища, классификация трафика и приватность — в [docs/analytics/backend.md](../analytics/backend.md), сквозные правила — в [implementation-contract.md](../analytics/implementation-contract.md).

## Ручки и их статус

| Ручка | Метод на фронтенде | Сейчас на бэкенде |
|---|---|---|
| `GET /cv/:linkId` | `getPublicResume` | реализована; выдаёт `X-View-Id` и cookie посетителя |
| `POST /cv/:linkId/contact-views` | `revealContact`, `revealContactsForDownload` | реализована для раскрытия одного контакта и выдачи всех контактов |
| `POST /cv/:linkId/events` | `sendAnalyticsBatch` (трекер шлёт через `sendBeacon`) | реализована |
| `GET /lk/link/:linkId/statistics` | `getLinkStatistics` | реализована |
| `GET /lk/link/:linkId/statistics/daily` | `getLinkDaily` | реализована |
| `GET /lk/link/:linkId/views` | `getLinkVisits` | реализована |
| `GET /lk/link/:linkId/statistics/sections` | `getLinkSections` | реализована |
| `GET /lk/link/:linkId/statistics/technologies` | `getLinkTechnologies` | реализована |
| `GET /lk/resume/:resumeId/statistics` | `getResumeStatistics` | реализована |
| `GET /lk/link/:linkId/clicks` | `getLinkClicks` | реализована |

Уведомления о переходах (Telegram-бот, настройки) в этот контракт не входят: фронтенд их пока не использует.

## Общие правила блока

**Идентификатор ссылки.** `linkId` в путях — это id *ссылки*, а не резюме. Один и тот же адрес `/cv/<linkId>` открывает публичная страница; в кабинете тот же id приходит из `GET /lk/links`.

**Авторизация.** `GET /cv/:linkId`, `POST …/contact-views` и `POST …/events` авторизации не требуют. Всё под `/lk/*` — как в остальных ручках кабинета (сессия владельца); чужая или несуществующая ссылка/резюме даёт `404`, а не `403`.

**Что попадает в цифры.** Во всех отчётах считаются только визиты с `traffic = human`. Боты (`bot`), владелец (`owner`) и подозрительные (`suspect`) хранятся, но в основные метрики не входят; их количество видно в поле `filtered`, а сами визиты — в ленте с `includeFiltered=true`.

**Открытие и прочтение.** *Открытие* (`views`) — один успешный `GET /cv/:linkId`. *Прочтение* (`reads`) — открытие, по которому сервер получил состояние `activeMs >= 5000`.

**Период.** Ручки отчётов принимают одни и те же параметры:

| Параметр | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `from` | дата `YYYY-MM-DD` | нет | в часовом поясе `tz`, **включительно** | 29 дней назад от `to` |
| `to` | дата `YYYY-MM-DD` | нет | в часовом поясе `tz`, **включительно**; не раньше `from` | сегодня в `tz` |
| `tz` | строка | нет | IANA-имя пояса (`Europe/Moscow`) | `UTC` |

Нарушение (`from` позже `to`, неизвестный `tz`, период длиннее 366 дней, дата не в формате) → `400`. Фронтенд всегда присылает все три параметра. Параметры периода игнорируют `views` (лента), `clicks` и поля `firstViewAt`/`lastViewAt` — это оговорено в каждой ручке.

**Время.** Моменты — `RFC 3339`, UTC (`2026-09-29T16:40:11Z`). Календарные дни (`date`) — в часовом поясе `tz`.

**Ошибки** — тело в общем формате ([README](README.md#базовые-правила)). В этом блоке:

| Статус | `code` | Когда |
|---|---|---|
| 400 | `BAD_REQUEST` | неверный период/параметр, невалидный JSON в `events` |
| 401 | `UNAUTHORIZED` | нет сессии у `/lk/*` |
| 403 | `FORBIDDEN` | не пройдена проверка на бота при раскрытии контакта |
| 404 | `NOT_FOUND` | ссылка/резюме нет или не ваши; резюме не опубликовано; `viewId` не принадлежит ссылке (`events`) |
| 409 | `CONFLICT` | контакт не скрыт (`contact-views`) |
| 410 | `GONE` | ссылка выключена |
| 413 | `REQUEST_TOO_LARGE` | тело `events` больше 32 КиБ |
| 429 | `TOO_MANY_REQUESTS` | лимит запросов |
| 500 | `INTERNAL_ERROR` | ошибка сервера |

## `GET /cv/:linkId` — выдача резюме и визит

Тело ответа — как в [public.md](public.md) (путь там назван `:resumeId`, это тот же id ссылки). Новое — в заголовках:

| Заголовок | Значение |
|---|---|
| `X-View-Id` | uuid нового визита. Выдаётся на **каждый** успешный `GET` опубликованной активной ссылки. Нет заголовка → визит не записан, трекер на фронтенде не запускается |
| `Set-Cookie` | cookie посетителя (`__Secure-cv_vid` в проде, `cv_vid` локально), если её ещё нет. `HttpOnly`, `Path=/api/v1/cv`, `SameSite=Lax`, год. Фронтенд её не читает |
| `Cache-Control` | `no-store` — иначе кеш «съест» визиты |

Ошибка записи визита не ломает выдачу: резюме отдаётся без `X-View-Id`. Выключенная ссылка → `410`, неопубликованное резюме или несуществующая ссылка → `404`; визит в этих случаях не создаётся.

Фронтенд: `getPublicResume` возвращает `{ resume, viewId }`, `viewId` сохраняется в состоянии страницы (`selectViewId`). Предпросмотр в кабинете грузит резюме через `GET /lk/resume/:resumeId` и визитов не создаёт.

## `POST /cv/:linkId/contact-views` — получение контактов

Одна ручка поддерживает раскрытие одного контакта и получение всех контактов для скачивания. `initiator` определяет формат ответа и аналитическое событие.

| Поле | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `initiator` | string | нет для старых клиентов | `contact` или `download` | `contact`, если передан `contact` |
| `contact` | string | при `initiator = contact` | `telegram`, `email`, `phone`; при `download` поле должно отсутствовать | — |
| `viewId` | uuid | нет | визит этой ссылки. Неизвестный или чужой `viewId` не привязывает событие; контакты всё равно возвращаются | отсутствует |
| `turnstileToken` | string | да, если включена проверка | токен Cloudflare Turnstile, до 2048 символов | отсутствует |

**Ответ `200` при `initiator = contact`:** `{ "contact": "telegram", "value": "a_sedletskii" }`.

**Ответ `200` при `initiator = download`:** массив содержит все сохранённые контакты, в том числе скрытые:

```json
{ "contacts": [{ "contact": "telegram", "value": "a_sedletskii" }, { "contact": "email", "value": "me@example.ru" }] }
```

Контакты без значения не включаются. Если контактов нет, возвращается пустой массив: `{ "contacts": [] }`.

**Аналитика.** После успешного раскрытия, если передан подходящий `viewId`, записывается `contact_view`. Получение контактов для файла само по себе событие скачивания не создаёт: после подготовки файла frontend отправляет одно событие `download` через `POST /cv/:linkId/events`. Так выдача скрытых контактов не дублирует метрику скачиваний. Ошибка записи `contact_view` не отменяет выдачу контакта.

Неизвестные поля тела → `400`. Ошибки: `400` (неверная комбинация `initiator`/`contact` или нет токена при включённой проверке), `403` (проверка Turnstile не пройдена), `404` (ссылка или запрашиваемый контакт не найден), `409` (при `contact`, если контакт не скрыт), `410`, `429`.

Frontend вызывает `revealContact` для `initiator: contact` и `revealContactsForDownload` для `initiator: download`. В обоих случаях `resumeId` — это `linkId` из адреса страницы.

## `POST /cv/:linkId/events` — события посетителя

Единый вход для всего клиентского потока: время на странице, дочитывание, действия, клики. Шлётся пачками раз в 15 секунд, при скрытии вкладки и при уходе со страницы.

**Транспорт.** `Content-Type` — `application/json` **или** `text/plain`: `navigator.sendBeacon` со строкой шлёт `text/plain`, и тело нужно разбирать как JSON независимо от заголовка. Куки отправляются (тот же origin).

**Тело:**

| Поле | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `viewId` | uuid | да | существующий визит **этой** ссылки, начатый не более 12 часов назад | — |
| `seq` | int | да | ≥ 1, растёт внутри визита; по нему упорядочивается `state` | — |
| `final` | bool | да | `true` — страницу закрывают (сервер ставит `ended_at`) | — |
| `state` | object | да | см. ниже | — |
| `events` | `Event[]` | да | до 100 штук | `[]` |
| `clicks` | `Click[]` | да | до 200 штук | `[]` |

`state`:

| Поле | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `activeMs` | int | да | ≥ 0; время видимой вкладки накопительно. Применяется монотонно: значение не уменьшается | — |
| `maxSection` | string | нет | `SectionId` из `layout.order` этого визита; «дальше» считается по индексу в нём | отсутствует |
| `exitSection` | string | нет | `SectionId`; секция на экране в момент отправки. Применяется по наибольшему `seq`. Не прислали — остаётся прежнее значение | отсутствует |

`Event`:

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `id` | uuid | да | идентификатор события на клиенте; пара `(viewId, id)` уникальна — повторная отправка не создаёт дубликат |
| `type` | string | да | один из типов ниже. **Серверные типы `view` и `contact_view` от клиента не принимаются** |
| `at` | int | да | время на клиенте, мс с 1970 г. Используется **только** для порядка внутри батча; время события на сервере — по часам сервера |

| `type` | Доп. поля | Когда |
|---|---|---|
| `section_view` | `section` (`SectionId`) | секция была на экране ≥ 40% высоты (или половину экрана) дольше секунды. Один раз за визит на секцию |
| `download` | — | скачали резюме. Теперь это всегда HTML, собранный на странице (файла автора больше нет): фронтенд сначала получает скрытые контакты (`contact-views`, `initiator = download`), собирает файл и после этого шлёт событие |
| `tech_filter` | `technology` (до 64 симв.), `action` (`select` \| `clear`) | выбрали или сбросили технологию в фильтре |
| `external_click` | `kind` (`project` \| `git` \| `contact` \| `other`), `target` (хост, до 64 симв.) | открыли внешнюю ссылку; полный адрес не шлётся |
| `print` | — | печать или «сохранить как PDF». Повтор в пределах 2 секунд считается дублем |
| `contact_copy` | `contact` | скопировали раскрытый контакт |
| `contact_click` | `contact` | перешли по контакту (t.me, mailto, tel) |

`Click`:

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `section` | string | да | `SectionId` |
| `x` | int | да | 0…10000 — сотые доли процента ширины секции, слева направо |
| `y` | int | да | 0…10000 — сотые доли процента высоты секции, сверху вниз |
| `vw` | int | да | ширина окна браузера; по ней выбирается брейкпоинт (`xs` < 600, `md` < 1200, `lg`) |
| `target` | string | нет | `data-analytics-id` элемента, до 64 символов |
| `at` | int | да | как у события |

Хеш версии секции (`layout_hash`) клик получает **на сервере** из снимка визита — клиент его не шлёт и не знает. В базе поля называются `x_pct`, `y_pct`, `viewport_w`; по сети — `x`, `y`, `vw`.

**Ответ `204`**, без тела, на любой валидный JSON. Невалидные отдельные события и клики молча отбрасываются (остальные обрабатываются): клиент не повторяет запросы, ошибка ему бесполезна. Батч от визита бота принимается (`204`), но не пишется.

**Ошибки:** `400` — не JSON; `404` — ссылки нет, резюме не опубликовано или `viewId` не принадлежит ссылке; `410` — ссылка выключена; `413` — тело больше 32 КиБ; `429` — лимит.

**Идемпотентность и порядок.** Повтор батча безопасен: события — по `(viewId, id)`, `state` — монотонно (`activeMs` не убывает, `maxSection` не возвращается назад, `exitSection` — по большему `seq`). Батчи могут прийти не по порядку.

Фронтенд: `createAnalyticsTracker` собирает батчи и шлёт через `sendBeacon` (с запасным вариантом `fetch` + `keepalive`); `sendAnalyticsBatch` — тот же контракт через axios.

## `GET /lk/link/:linkId/statistics` — сводка по ссылке

Параметры — период (`from`, `to`, `tz`). Тела нет.

**Ответ `200`:**

| Поле | Тип | Описание |
|---|---|---|
| `views` | int | открытия за период |
| `reads` | int | прочтения за период |
| `uniqueVisitors` | int | уникальные посетители за период |
| `returningVisitors` | int | из них заходившие в разные дни |
| `contactViews` | int | раскрытия контактов |
| `downloads` | int | скачивания резюме |
| `firstViewAt` | datetime \| null | первый просмотр за **всё время** (не за период); `null`, если просмотров не было |
| `lastViewAt` | datetime \| null | последний просмотр за всё время |
| `medianActiveSeconds` | int | медианное время на странице среди прочтений за период; `0`, если прочтений нет |
| `devices` | object | `{ desktop, mobile, tablet, unknown }` — число открытий; все четыре ключа есть всегда |
| `referrers` | `{ host: string \| null, views: int }[]` | источники по убыванию; `host: null` — напрямую, без реферера; только хост, без пути |
| `filtered` | object | `{ bot, owner, suspect }` — сколько визитов за период отфильтровано |

Поля `views` и `contactViews` уже есть в ответе сейчас и сохраняются; `views` начинает означать открытия людей.

Фронтенд также запрашивает **предыдущий период** той же длины (`getPreviousRange`) для сравнения; ошибка этого запроса необязательна.

## `GET /lk/link/:linkId/statistics/daily` — по дням

Параметры — период. **Ответ `200`:** `{ "days": DailyPoint[] }`, где `DailyPoint`:

| Поле | Тип | Описание |
|---|---|---|
| `date` | `YYYY-MM-DD` | календарный день в `tz` |
| `views` | int | открытия |
| `reads` | int | прочтения |
| `uniqueVisitors` | int | уникальные посетители |

Все дни периода идут подряд по возрастанию; дни без визитов приходят с нулями — заполняет сервер.

## `GET /lk/link/:linkId/views` — лента визитов

От периода **не зависит**: отдаётся вся история в пределах хранения (12 месяцев), новые сверху.

| Параметр | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `cursor` | string | нет | непрозрачный курсор из `nextCursor` | с начала |
| `limit` | int | нет | 1…50 | `20` |
| `includeFiltered` | bool | нет | `true` добавляет ботов, владельца и подозрительных (у каждого свой `traffic`) | `false` |

**Ответ `200`:** `{ "items": Visit[], "nextCursor": string | null }`. Пагинация по `(startedAt, id)`; `nextCursor: null` — конец.

`Visit`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid | идентификатор визита (`viewId`) |
| `startedAt` | datetime | начало визита |
| `visitor` | object | `{ ordinal: int, isReturning: bool }` — порядковый номер посетителя **в рамках ссылки** («Посетитель №2») и заходил ли он раньше. Сам идентификатор посетителя не отдаётся |
| `device` | string | `desktop`, `mobile`, `tablet`, `unknown` |
| `browser` | string | `chrome`, `safari`, `firefox`, `edge`, `yandex`, `other` |
| `os` | string | `windows`, `macos`, `linux`, `ios`, `android`, `other` |
| `referrerHost` | string \| null | хост источника или `null` |
| `isRead` | bool | визит стал прочтением |
| `activeSeconds` | int | время на странице |
| `maxSection` | string \| null | самая дальняя секция; `null`, если данных нет |
| `exitSection` | string \| null | секция на экране при уходе |
| `events` | `VisitEvent[]` | действия посетителя по времени (см. ниже); без действий — `[]`, не `null` (фронт на всякий случай приводит `null` к `[]`) |
| `traffic` | string | `human`, `bot`, `owner`, `suspect` |

`VisitEvent`: `{ type, at }` + поля по типу. В `events` отдаются **только действия**: `contact_view`, `contact_copy`, `contact_click` (поле `contact`), `tech_filter` (`technology`), `download`, `print`, `external_click` (`kind`, `target`). Служебные `section_view` не отдаются. `at` — серверное время (RFC 3339); фронтенд показывает смещение от `startedAt`.

## `GET /lk/link/:linkId/statistics/sections` — до какой секции дочитывают

Параметры — период. Считается только по прочтениям (у открытий без JS данных о секциях нет).

**Ответ `200`:**

| Поле | Тип | Описание |
|---|---|---|
| `reads` | int | прочтений за период (база для долей) |
| `sections` | `{ section, reached, exits }[]` | `reached` — прочтения, в которых был `section_view` этой секции; `exits` — прочтения с такой `exitSection` |

Значения считаются по идентификаторам секций из событий и не зависят от порядка на странице. Строки идут в **текущем** порядке секций резюме; секции, которых уже нет на странице, могут идти в конце. Фронтенд в любом случае пересортировывает ответ по порядку открытого резюме.

## `GET /lk/link/:linkId/statistics/technologies` — интерес к стеку

Параметры — период. **Ответ `200`:** `{ "technologies": { name, selections, visitors }[] }` — по убыванию `selections`, не больше 20; `selections` — сколько раз выбрали, `visitors` — сколько разных посетителей. Нет выборов → `[]`.

## `GET /lk/resume/:resumeId/statistics` — сводка по резюме

Параметры — период. **Ответ `200`:** все поля [сводки по ссылке](#get-lklinklinkidstatistics--сводка-по-ссылке) за все ссылки резюме вместе, плюс:

| Поле | Тип | Описание |
|---|---|---|
| `links` | `{ id, name, views, reads, lastViewAt }[]` | разбивка по ссылкам резюме (`lastViewAt` — `null`, если открытий не было) |

Нужна для сводки на «Главной» резюме и счётчиков у ссылок.

## `GET /lk/link/:linkId/clicks` — карта кликов

От периода **не зависит**: берутся все клики в пределах хранения (90 дней).

| Параметр | Тип | Обяз. | Ограничения | Дефолт |
|---|---|---|---|---|
| `section` | string | да | `SectionId` | — |
| `breakpoint` | string | да | `xs` (< 600 px), `md` (< 1200 px), `lg` | — |
| `includeStale` | bool | нет | `true` добавляет клики по прежним версиям секции | `false` |

**Ответ `200`:**

| Поле | Тип | Описание |
|---|---|---|
| `section` | string | запрошенная секция |
| `grid` | int | размер сетки, сейчас `20` |
| `cells` | `{ x, y, count }[]` | непустые клетки: `x`, `y` — `0…grid-1`, `count` — число кликов (> 0) |
| `total` | int | сумма `count` по `cells` |
| `staleTotal` | int | кликов по прежним версиям секции, **не вошедших** в сетку (при `includeStale=true` — `0`) |

По умолчанию в сетку попадают только клики на **текущую** версию секции (`layout_hash`, который сервер считает по резюме в момент запроса): координаты — доли секции, и после правки секции они указывают мимо.

## Открытые вопросы

Это предложения фронтенда там, где документы бэкенда молчат или противоречат друг другу. Пока бэкендер не решил иначе, фронтенд ведёт себя так, как написано выше.

1. **Имена полей клика** — по сети `x`, `y`, `vw`, в базе `x_pct`, `y_pct`, `viewport_w`. В `implementation-contract.md` §6 по сети названы колонки БД; надо поправить там.
2. **`to` включительно** (и `from` тоже) в часовом поясе `tz` — в документах бэкенда не оговорено.
3. **`techStack` отследить нельзя**: слайдер стека не рендерится как секция, поэтому для него не бывает `section_view` и кликов. Предлагается не включать его в `layout.order` и воронку (или фронтенд сделает его секцией — тогда скажите).
4. **Неизвестный `viewId` в `contact-views` игнорируется**, а не даёт ошибку: раскрытие контакта критичнее, чем привязка к визиту.
5. **Do Not Track / Global Privacy Control.** Фронтенд при них не запускает трекер и не шлёт `viewId` в `contact-views`. Сервер должен читать заголовки `DNT: 1` и `Sec-GPC: 1` и не ставить cookie посетителя. Раскрытие без `viewId` по документу «в отчёт не идёт» — тогда такие раскрытия потеряются; решить, считать ли их.
6. **История просмотров.** Если `resume_link_views` — единственный источник, прежние события `view` из отчётов пропадут. Нужен бэкфилл или явное решение, что история обнуляется.
7. **Визиты ботов.** «Батч принимаем, но не пишем» противоречит принципу «помечаем, а не выбрасываем»: в ленте с `includeFiltered` у таких визитов не будет времени и действий. Для `owner` и `suspect` правило не задано.
8. **Защита от накрутки.** Лимиты (100 событий, 200 кликов) заданы на батч; нужен лимит на **визит**. Серверные типы (`view`, `contact_view`) из клиентских батчей должны отклоняться.
9. **Батч после `final`** (возврат из bfcache): принимать и снимать `ended_at` до следующего `final`.
10. **Лимит запросов на `events`** не должен совпадать с жёстким лимитом раскрытий (3 в минуту): трекер шлёт несколько запросов в минуту.
11. **Хеш секции**: зафиксировать каноническую форму и версию алгоритма, иначе смена алгоритма разом «устарит» все клики.
12. **Раскрытие посетителю.** `backend.md` («Приватность») требует строку в футере публичной страницы, а фронтенд показывает плашку справа снизу (закрывается кнопкой «Понятно»). Формулировку «без персональных данных» стоит заменить: cookie с идентификатором и хеш IP — псевдонимизация, а не анонимность; фронтенд пишет «обезличенный идентификатор».
13. **`initiator` и обратная совместимость.** Открытые вкладки и закешированный бандл ещё шлют тело без `initiator`. На время выката сервер должен принимать такое тело как `initiator = contact`, иначе раскрытие контактов у них сломается.
14. **Лимит на пачку.** Лимит раскрытий (3 в минуту) считает запрос, а не контакт, и один `download` отдаёт до трёх контактов; решить, считать ли пачку за один запрос или за число контактов. Ещё: кнопка «Скачать» — удобный способ вытащить все контакты скрейпером, защита та же (Turnstile + лимит), и лимит стоит выбирать с этим в виду.
15. **`resumeLink` удалён из интерфейса.** Бэкенд ещё принимает и отдаёт `resumeLink` в обзоре и хранит его в `resume_overviews.resume_link`; поле можно убрать вместе с миграцией. До этого `PUT …/overview` без поля очищает прежнее значение — это ожидаемо.
